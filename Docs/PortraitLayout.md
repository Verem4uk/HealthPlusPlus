# Адаптивный интерфейс: телефоны, планшеты и компьютер

Графическое обновление от 27 ноября: см. `Docs/GraphicsTheme.md`.
Описанная ниже первоначальная компоновка обновлена: фон теперь зелёный,
меню помещается в рамку без обрезки, центральная колонка ограничивается также
высотой, а WebGL canvas заполняет всю ширину, включая Full HD. Базовые проверки
расширены до 11 профилей телефонов, планшетов и компьютеров.

`SampleScene` использует Scale With Screen Size / Expand с базой 1080 × 1920.
Оба корневых Canvas получили SafeArea и PortraitContent. Ширина содержимого ограничена
1080 UI-единицами; на широких вертикальных экранах остаются боковые поля. Runtime-компонент
`PortraitTrainingLayout` реагирует на изменение размеров canvas и безопасной области.

Существующие ссылки Controller, обработчики кнопок и анимация кнопки меню сохранены.
Кнопка меню поднята относительно нижнего края с запасом под полный поворот и пульсацию.
Установка повторно выполняется через **Health++ → Apply portrait layout**;
`HealthPortraitInstaller` также вызывается редакторской проверкой перед сохранением сцены.

## Видео и изображения

- Фон меню и его видео остаются за элементами управления. Прямоугольник фона сохраняет
  пропорции исходного изображения и заполняет экран (Envelope Parent), обрезая края.
- Картинка и видео упражнения находятся в отдельном ExerciseMediaFrame между счётчиком
  и нижними кнопками. Видео использует Fit In Parent, картинка — preserveAspect;
  содержимое видно целиком, свободное место занимает тёмный фон.
- Панель ввода выполненного количества использует отдельные области для заголовка,
  числа, кнопок плюс/минус и подтверждения. Проверен счётчик до шести цифр.

Встроенные VideoClip меню ещё нужно заменить URL-источниками для WebGL (см.
`Docs/WebGLPreflight.md`). Проверки пропорций не подтверждают реальное воспроизведение
видео в браузерной сборке.

## Страница WebGL

HTML использует всю доступную динамическую высоту браузера, CSS safe-area-inset и
реальную высоту верхней строки состояния. `portrait-viewport.mjs` через ResizeObserver
подбирает размер canvas в оставшейся области; фиксированного вычитания 70 px больше нет.
Canvas не шире соотношения 3:4; Unity дополнительно ограничивает колонку содержимого.
Панели входа, обязательной регистрации и выбора сохранения не выходят за ширину экрана;
кнопки имеют высоту не менее 48 CSS px.

По просьбе пользователя обработка поворота не добавлялась: нет orientation listeners,
просьбы повернуть устройство, блокировки браузера или новых обработчиков паузы таймера.
Горизонтальный интерфейс не проектировался и не тестировался. В native Player Settings
выбрана фиксированная Portrait orientation, autorotate в остальные положения выключен.

## Полноэкранный режим

Как в `EggO/Build/EggO.html`, после успешной загрузки Unity первый pointerdown на canvas
запрашивает полноэкранный режим напрямую, сохраняя пользовательскую активацию браузера.
Полноэкранной становится вся HTML-страница, чтобы панели аккаунта и управление были
доступны и после гостевой тренировки. Кнопка Full screen / Exit full screen позволяет
выйти и войти повторно. После выхода следующий игровой тап не затягивает пользователя
обратно автоматически. На загрузке страницы и на кнопках Google fullscreen не запрашивается.

`fullscreen.mjs` поддерживает стандартный и WebKit API. Если API отсутствует или браузер
отклоняет запрос, приложение продолжает работать в обычном адаптивном окне. Изменений
ориентации экрана нет. Поддержку на реальном Safari/iPhone следует проверить отдельно.

Изменения внесены в шаблон и уже готовый `Build/index.html`. Для текущей публикации
достаточно обновить `index.html` и добавить `fullscreen.mjs` рядом с ним; сборка Unity
для этой правки не требуется.

## Проверки

Unity: 320×568, 360×780, 390×844, 430×932, 1080×2400, 768×1024, 820×1180, 1024×1366,
каждый профиль с безопасными отступами и без них. Проверены попадание элементов в safe
area, отсутствие пересечений, длинные числа, ограничение ширины и видео 9:16, 16:9,
1:1 и примерно 0.45:1. Получено 594 успешных проверки и снимки меню/тренировки/регрессии.

Браузер: 320×568, 360×780, 390×844, 430×932, 432×960, 768×1024, 820×1180, 1024×1366.
Реальные HTML/CSS и модуль viewport проверены в Chromium на трёх панелях аккаунта,
с имитацией safe-area padding и без неё. Получено 336 успешных проверок. Браузерный тест
не запускает Unity player и не выполняет запросы к Firebase.

Снимки и результаты: `Logs/PortraitLayout/` и `Logs/PortraitLayout/Web/` (не включаются в Git).

Повторный запуск (без сборки приложения):

```powershell
& 'D:/Programs/6000.1.6f1/Editor/Unity.exe' -batchmode -force-d3d11 -projectPath 'D:/Repositories/Health++' -executeMethod HealthPortraitLayoutTests.Run -logFile 'D:/Repositories/Health++/Logs/portrait-layout-tests.log'
node Tests/Portrait/browser-layout.cjs
node --test Tests/Portrait/fullscreen.test.mjs
node Tests/Portrait/browser-fullscreen.cjs
```

Для браузерной проверки нужны Playwright и установленный Chromium. Реальные Safari/iOS,
Android, вырезы устройств, касания и декодирование видео следует проверить после WebGL-сборки.
