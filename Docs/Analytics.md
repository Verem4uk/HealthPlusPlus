# Минимальная аналитика WebGL

Firebase Analytics подключается к существующему Firebase app и Measurement ID
`G-NRL60B0BHE`. Инициализация идёт отдельно от входа и сохранений: неподдерживаемый
браузер, блокировщик или ошибка SDK не прерывают приложение.

| Событие | Когда | Параметры |
| --- | --- | --- |
| `login` | Успешный явный вход через Google | `method: Google` |
| `app_ready` | Unity загрузилась и восстановила сохранение | — |
| `guest_started` | Пользователь впервые выбрал гостевую тренировку | — |
| `guest_sign_in_prompt` | Гость завершил тренировку и увидел обязательный вход | `level` |
| `guest_converted` | После гостевого режима успешно выполнен вход через Google | `account_type: new / existing` |
| `training_start` | Началась доступная тренировка | `level`, `base_number` |
| `training_complete` | Тренировка завершена и выполнено локальное сохранение | `level`, `duration_seconds` |

У всех событий есть `platform: webgl` и `account_status: guest / registered`.
Статус фиксируется в момент события, в том числе когда оно ожидает инициализации SDK.
Уровень начинается с 1 и соответствует уровню
на старте тренировки, включая завершение с переходом на следующий уровень.
Длительность — прошедшее время с начала тренировки, включая нахождение страницы в фоне;
это не сумма времени выполнения упражнений. Завершение не означает подтверждение
сохранения сервером — очередь синхронизации работает отдельно.

Автоматическое восстановление входа не отправляет `login` повторно. `app_ready`
отправляется один раз за загрузку страницы. Firebase также собирает стандартные
веб-события посещения и сессий. Дополнительный код gtag/Analytics в HTML вставлять
не нужно: двойная инициализация приведёт к неверному подсчёту.

Воронка для анализа гостей: `guest_started` → `guest_sign_in_prompt` → `guest_converted`.
Гостей, не завершивших вход за выбранный период, нужно считать по отсутствию последнего
шага в воронке пользователей. Отдельное событие «никогда не зарегистрировался» не
отправляется: закрытие вкладки не означает окончательный отказ. Возврат в том же браузере
может завершить конверсию позже. `account_type: new` означает создание нового аккаунта
Firebase, `existing` — вход в существующий. Конверсия отражает успешный вход, а не
подтверждение отправки прогресса сервером.

Пользовательские события используют фиксированный список параметров. Email, имя,
Firebase UID и содержимое сохранения в них не передаются. Google Signals и
персонализация рекламы отключены. Между устройствами идентификаторы Analytics
этой реализацией не объединяются.

## Проверка после размещения

1. Открыть `https://verlema.life/HealthPlusPlus/?analytics_debug=1`.
2. В Firebase Console открыть Analytics → DebugView. На чистом гостевом профиле выбрать
   гостя, начать и завершить тренировку, затем войти через Google. Проверить события
   гостевой воронки, `app_ready`, `login`, `training_start` и `training_complete`.
3. Проверить параметры уровня и длительности. Для обычного тестирования открывать
   ссылку без `analytics_debug=1`.
4. Для разреза обычных отчётов по уровню зарегистрировать event-scoped custom dimension
   для параметра `level` в Google Analytics → Admin → Custom definitions. Для числового
   анализа длительности — custom metric `duration_seconds`, единица измерения Seconds.
   До регистрации параметры можно проверять в DebugView.
5. Для сегментации воронки зарегистрировать event-scoped custom dimensions для
   `account_status` и `account_type`. Сравнивать пользователей по шагам воронки, а не
   вычитать общее число событий: один пользователь может тренироваться много раз.

Наличие Measurement ID в конфиге не подтверждает доставку событий: реальная отправка
в DebugView пока не проверена. WebGL-сборка по просьбе пользователя отложена.

Локальные проверки: `node --test Tests/CloudProgress/*.test.mjs`.

Документация: [Get started](https://firebase.google.com/docs/analytics/get-started?platform=web),
[Analytics JS API](https://firebase.google.com/docs/reference/js/analytics),
[DebugView](https://firebase.google.com/docs/analytics/debugview).
