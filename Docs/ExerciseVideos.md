# Видео упражнений

В `ExerciseSO` заполнить поле **Video Url** прямой HTTPS-ссылкой на MP4.
Пустое поле сохраняет показ `Icon`. Ссылки на страницы видеохостингов и AssetBundle не подходят.
Видео воспроизводятся без звука, по кругу. Рекомендуемый исходный формат — MP4/H.264.

## Загрузка и показ

- `TrainingVideoBootstrap` запускает подготовку сохранённого текущего уровня при старте приложения.
- `TrainingVideoCoordinator` использует тот же каталог `Controller.TrainingLevels`, что и тренировка.
  URL обрабатываются в порядке `Level.Exercises`; повторяющиеся и пустые адреса пропускаются.
- `VideoLoader` — обычный C#-класс без `MonoBehaviour`. Скачивает последовательно, объединяет
  одновременные запросы одного URL и использует готовые локальные копии. Ошибочная загрузка
  повторяется координатором один раз, затем очередь продолжает работу.
- При смене текущего уровня подготавливается его очередь; ранее скачанные файлы остаются доступными.
- `Controller` проверяет готовность ролика только при открытии упражнения.
  `ExerciseMediaView` показывает картинку до первого декодированного кадра и при ошибке видео.
  Если ролик ещё не скачан, упражнение целиком проходит с картинкой: завершение загрузки
  не переключает текущий экран. Для просмотра ролика нужно открыть упражнение заново.

Загрузка, воспроизведение демонстрации и таймер Plank независимы. `Trainer` не обращается к сети.

## Кеш и платформы

Файлы сохраняются в `Application.persistentDataPath/ExerciseVideos`. Имя — SHA-256 полного URL.
До завершения скачивания используется расширение `.part`; только успешно скачанный файл
с MP4-заголовком переносится в готовую библиотеку. Полную проверку декодирования выполняет VideoPlayer.
Одинаковые URL между уровнями используют одну копию. Автоматического удаления готовых роликов нет.

На Android, iOS и в Editor воспроизводится локальный `file:` URL. В WebGL загрузчик сохраняет
файл в виртуальной файловой системе, синхронизирует её с IndexedDB и создаёт Blob URL для
видеоплеера. `VideoSourceResult.Dispose()` освобождает Blob URL при смене упражнения.
Браузер может удалить данные сайта; в этом случае ролики будут скачаны повторно.
Сервер должен разрешать CORS-запросы с адреса WebGL-приложения и использовать HTTPS.

Готовый файл не проверяется на сервере при каждом запуске. Для новой версии ролика нужен
новый URL, например `plank_v2.mp4`. Сейчас URL находятся в локальных SO, поэтому изменение
адреса требует обновления приложения. Удалённый каталог версий в этой реализации не предусмотрен.

## Проверки

Проверены в Unity Play Mode через локальный HTTP-сервер: порядок и повторы запросов,
кеш между экземплярами загрузчика, общий запрос для нескольких потребителей, отмена ожидания,
удаление незавершённых файлов, восстановление повреждённого кеша, реальное воспроизведение
и зацикливание MP4, возврат к картинке и независимость отображения от загрузок.
Также пройдены проверки логики существующей тренировки, компиляция WebGL-ветки C# и
проверки JavaScript-моста с имитацией браузерного хранилища.

На устройствах Android/iOS и в браузерной сборке WebGL воспроизведение ещё не проверялось.
