# Оформление Health++

Согласованный вариант: тёмно-зелёная фактурная подложка, боковой орнамент,
металлические рамки, оригинальные персонажи, логотип, цифры и щиты.
На стартовом экране нет плашки «Начать тренировку». Кнопка-щит сохраняет
поворот при переходе дня/ночи и пульсацию при доступной тренировке.
Подсветка тёплая золотистая и слабая: alpha 0.15, небольшая модуляция 0.012.
Декоративные элементы не перехватывают нажатия.

## Компоновка

`PortraitTrainingLayout` ограничивает центральную колонку шириной 1080 UI-единиц,
доступной шириной и 56.25% доступной высоты. На компьютере расширяется зелёная
подложка; персонажи, цифры и кнопки не растягиваются на всю ширину.
В браузере canvas теперь занимает весь игровой viewport, а не ограничивается 3:4.

Меню сохраняет пропорции Day/Night. Логотип находится внутри рамки в верхней
части заставки. Картинка и видео упражнения сообщают свои реальные пропорции
компоновщику; рамка подстраивается под них. Материалы не обрезаются и не
перегенерируются. На экране упражнения добавлены название, единицы измерения
и подписи к действиям. Пустой польский перевод названия использует английский.
Панель ввода результата использует ту же тему и металлические цифры.

В WebGL верхняя строка содержит статус сохранения, fullscreen, звук и аккаунт.
Выход находится в раскрывающемся меню аккаунта. Настройка звука сохраняется
локально и применяется к AudioListener и прямому звуку VideoPlayer.
Вход во время незавершённой гостевой тренировки недоступен, чтобы не заменять
её состояние. Существующие Google/Firebase обработчики сохранены.

## Исходные материалы

Проверка заголовков MP4 показала, что разрешения различаются:

| Файл | Разрешение |
| --- | --- |
| FromNightToDay | 720×1600 |
| FromDayToNight | 966×2148 |
| Squat0, Squat1, PushUp3, PushUp4 | 720×1280 |
| PushUp0, PushUp1 | 1080×1920 |
| PushUp2 | 966×2148 |

Поэтому фиксировать одну пропорцию для всех роликов нельзя. Встроенный в
Playwright Chromium не сообщает видеопоток для части файлов; размеры для них
получены из tkhd MP4. Это не проверка воспроизведения во всех пользовательских
браузерах. Подробный локальный отчёт: `Logs/Graphics/media-audit.json`.

WebGL не воспроизводит импортированные VideoClip. `HealthMenuVideoBuild`
копирует два оригинальных MP4 после сборки в `StreamingAssets/Menu/`,
а WebGL-ветка `MainMenuTransitionView` открывает эти URL. В Editor/native
остаются исходные VideoClip. Видео не перекодируются.

## Файлы оформления

- `Assets/Images/Theme/forest-green.png`: зелёная текстура.
- `Assets/Images/Theme/forged-frame.png`: рамка с прозрачным центром, nine-slice.
- `Assets/Images/Theme/sun-glow.png`: радиальный градиент, построенный кодом Unity.
- `VikingOrnament`: масштабируемый орнамент из UI-геометрии.
- `Assets/WebGLTemplates/HealthCloud/theme.*` и `theme-*.svg/png`: браузерная тема.

Текстура и рамка созданы встроенным image_gen. Точные запросы сохранены в
`Docs/GraphicsAssets.prompts.txt`. Это новые вспомогательные ассеты;
исходные изображения, логотип, щиты и ролики сохранены.

Применить оформление повторно: **Health++ → Apply portrait layout**.
Установка идемпотентна; повторное применение не дублирует объекты сцены.

## Проверки и сборка

```powershell
& 'D:/Programs/6000.1.6f1/Editor/Unity.exe' -batchmode -force-d3d11 -projectPath 'D:/Repositories/Health++' -executeMethod HealthPortraitLayoutTests.Run -logFile 'D:/Repositories/Health++/Logs/graphics-layout-tests.log'
node Tests/Portrait/verify-browser.cjs
node --test Tests/Portrait/fullscreen.test.mjs Tests/CloudProgress/*.test.mjs
```

Профили: 320×568, 360×780, 390×844, 430×932, 1080×2400, 768×1024,
820×1180, 1024×1366, 1366×768, 1920×1080, 2560×1440, с safe area и без неё.
Unity проверяет границы элементов, сохранение пропорций, отсутствие перекрытий,
длинные счётчики и отсутствие перехвата ввода декором; сохраняет снимки
меню, тренировки и ввода результата в `Logs/PortraitLayout/`.

Отдельная сборка:

```powershell
& 'D:/Programs/6000.1.6f1/Editor/Unity.exe' -batchmode -force-d3d11 -buildTarget WebGL -projectPath 'D:/Repositories/Health++' -executeMethod HealthGraphicsBuild.Run -logFile 'D:/Repositories/Health++/Logs/graphics-build.log'
node Tests/Portrait/browser-player.cjs
```

Выход: `Build/GraphicsUpdate/`. Предыдущая сборка в `Build/` сохраняется.
`browser-player.cjs` открывает настоящий собранный плеер с отключённым SDK
аккаунта, запускает гостевую тренировку и снимает экраны на компьютере и телефоне.
Для localhost тест добавляет CORS-заголовок к ответам оригинальных роликов;
при размещении приложения и роликов на одном origin это не требуется.
Снимки сохраняются в `Logs/Graphics/`. Публикацию на сервер проверка не выполняет.

Результаты от 27 ноября 2026: 1147 проверок компоновки Unity, 462 проверки
браузерной компоновки, отдельные проверки fullscreen, звука и меню аккаунта,
31 тест сохранений/гостя/аналитики/fullscreen. WebGL-сборка успешно создана.

Автостарт перехода без клика проверяется отдельно:
`node Tests/Portrait/browser-startup.cjs`. Проверка запускает готовый WebGL-плеер
в новом браузерном контексте без флага отключения autoplay, восстанавливает
прогресс и ждёт реального воспроизведения MP4. В первую опубликованную сборку
MP4 в `StreamingAssets/Menu/` ещё не входили: импортированный VideoClip был
недоступен в WebGL, и меню сразу показывало финальный дневной фон.
Для обновления сайта нужны и файлы Build, и каталог StreamingAssets/Menu.
Проверка опубликованной версии 27 ноября подтвердила старый loader
`43933d99d00b4d008087ca456d12b9cd.loader.js` и HTTP 404 для
`/HealthPlusPlus/StreamingAssets/Menu/FromNightToDay.mp4`. В новой локальной
сборке файл присутствует; браузерная проверка без кликов успешно воспроизводит его.
