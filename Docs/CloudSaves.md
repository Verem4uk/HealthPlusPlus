# Облачное сохранение MVP (WebGL)

Реализация подготовлена для Firebase Authentication (Google) и Cloud Firestore.
В `firebase-config.js` добавлен публичный конфиг проекта `healthplusplus-55945`.
Настройки Authentication и Firestore в консоли пока не проверены, правила из репозитория
не опубликованы. Реальная авторизация и браузерная сборка ещё не проверены.

## Подключение

1. Открыть проект `healthplusplus-55945` в Firebase Console. Web app уже зарегистрировано.
2. Публичный `firebaseConfig` уже записан в
   `Assets/WebGLTemplates/HealthCloud/firebase-config.js`.
   Для сохранений используются Authentication и Firestore; минимальная Analytics
   инициализируется отдельно и не блокирует их (см. `Docs/Analytics.md`).
3. В Authentication → Sign-in method включить Google. В Settings → Authorized domains
   добавить домен тестовой сборки (для локального тестирования также `localhost`).
4. Создать базу Cloud Firestore `(default)`. Применить правила из `Firebase/firestore.rules`.
   Если в базе уже есть приложения, **объединить** эти правила с существующими:
   файл описывает только коллекцию Health++ и не заменяет правила других приложений.
   Убедиться, что существующее общее правило не открывает доступ к этой коллекции.
5. Собрать WebGL с шаблоном `HealthCloud` (уже выбран в Project Settings).
   Разместить сборку на HTTPS-хостинге с заголовками сжатия, соответствующими Unity Build.
   Firebase Hosting также подходит; публиковать ничего автоматически эта интеграция не будет.

## Поведение

- На первом запуске страница предлагает **Sign in with Google** или **Continue as guest**.
  Google popup открывается только по нажатию кнопки. Уже вошедшему пользователю выбор
  повторно не показывается: приложение загружает его сохранение.
- Гостю доступна одна завершённая тренировка. После завершения появляется обязательное
  предложение: **Great job completing your first workout! To save your progress and continue
  training, sign in with Google.** Кнопки пропуска нет. Гостевой результат сохраняется отдельно
  в localStorage, а Unity блокирует начало следующей тренировки до входа.
- При повторном открытии страницы гость с завершённой тренировкой сразу видит предложение
  войти; повторная гостевая тренировка через перезагрузку недоступна. Очистка хранилища
  браузера сбрасывает гостевой режим; это ограничение интерфейса MVP, а не серверная защита
  от обхода регистрации.
- После входа гостевой прогресс переносится в очередь конкретного UID. Для пустого аккаунта
  перенос автоматический; если в аккаунте уже есть другой результат, пользователь выбирает
  между ним и гостевой тренировкой. Автоматической перезаписи существующего прогресса нет.
  Копия, уже привязанная к аккаунту, не переносится автоматически в другой аккаунт.
- Для аккаунта перед разблокировкой Unity загружается серверное сохранение. Без первого
  успешного чтения облачная тренировка недоступна: пустой прогресс не записывается поверх
  существующего. Гостевая тренировка не требует доступности Firebase SDK.
- Один документ `healthPlusPlusProgress/{uid}` хранит уровень, базовую нагрузку и день
  последней завершённой тренировки. Язык остаётся настройкой устройства.
- Сохранение отправляется после **завершённой тренировки**, вместе с локальной записью.
  Незавершённая тренировка после перезагрузки не возобновляется.
- Очередь отправки хранится в `localStorage` отдельно для каждой пары projectId/UID.
  При потере сети повторная отправка выполняется раз в 15 секунд, при восстановлении сети
  и при следующем входе. Надпись «сохранено в облаке» появляется после подтверждения сервера.
- Начало новой сессии аккаунта требует подключения к серверу. После загрузки тренировка может
  завершиться без сети; её результат останется в очереди на этом устройстве.
- Транзакция сравнивает ревизию: устаревший клиент не перезаписывает другой прогресс.
  При конфликте пользователь явно выбирает облачную или локальную копию.
  Идентификатор операции позволяет повторить запрос после потерянного ответа без двойной записи.
- Web Locks разрешает только одну вкладку приложения на пользователя. Нужен современный
  браузер с Web Locks и HTTPS (localhost допускается браузерами для разработки).
- Вход в другой аккаунт перезагружает страницу, а затем восстанавливает его сохранение.
  Очередь предыдущего аккаунта остаётся привязана к его UID.
- Очистка браузера удаляет локальную очередь: неподтверждённые сервером изменения могут
  потеряться. Подтверждённый прогресс восстанавливается после входа в тот же Google-аккаунт.
- Android/iOS/Editor продолжают использовать локальное сохранение. Firebase для нативных
  сборок пока не подключён. Старые PlayerPrefs не импортируются автоматически: гостевой
  WebGL-прогресс ведётся отдельно и переносится описанным выше способом.

## Проверки перед раздачей

Автотесты очереди, аналитики и гостевого сценария: `node --test Tests/CloudProgress/*.test.mjs`.

На реальном проекте проверить вход и возврат после перезагрузки; восстановление на втором
устройстве; завершение без сети и отправку после её появления; конфликт двух устройств;
выход и вход другим пользователем; запрет чтения и записи чужого UID через Rules Simulator
или Emulator Suite. Не заменять эти проверки только компиляцией C#.

Остаётся отдельная работа для WebGL-релиза: видео переходов меню используют встроенные
VideoClip; для браузера их нужно перевести на URL. Облачное сохранение этого не исправляет.
